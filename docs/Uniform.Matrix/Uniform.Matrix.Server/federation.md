# Federation

Federation is being built, behind `Federation:Enabled`. In `Federation/`:

- [`ServerResolver`](xref:Uniform.Matrix.Server.Federation.ServerResolver) finds other servers as the spec's [server name resolution](https://spec.matrix.org/latest/server-server-api/#resolving-server-names) says: IP literals and names with a port directly, otherwise `/.well-known/matrix/server` delegation, else port 8448. SRV records are not looked up yet.
- [`FederationClient`](xref:Uniform.Matrix.Server.Federation.FederationClient) sends requests signed with [`FederationAuth`](xref:Uniform.Matrix.Protocol.Server.FederationAuth) (in `Uniform.Matrix.Protocol.Server`) as an `X-Matrix` authorization, through the same public-addresses-only handler as push gateways and URL previews.
- [`RemoteServerKeys`](xref:Uniform.Matrix.Server.Federation.RemoteServerKeys) fetches other servers' keys from their `/_matrix/key/v2/server`, else from the key servers of `Federation:TrustedKeyServers` (whose own signature is checked too), accepts them only when every listed key signed the answer, and keeps the answer in `ServerKeyResponses` until `valid_until_ts`, at most a week. Old keys count for signatures too, and when nothing can be fetched the last answer is used even when expired. `/_matrix/key/v2/query` answers as a key server, each answer countersigned.
- [`ServerAuthentication`](xref:Uniform.Matrix.Server.Federation.ServerAuthentication) is middleware on endpoints marked [`RequireFederation()`](xref:Uniform.Matrix.Server.Federation.ServerAuthentication.RequireFederation*): it buffers the body, checks the signature over the raw request target, and gives the endpoint the origin with [`GetOrigin()`](xref:Uniform.Matrix.Server.Federation.ServerAuthentication.GetOrigin*).

[`FederationEndpoints`](xref:Uniform.Matrix.Server.Endpoints.FederationEndpoints) serves `/_matrix/key/v2/server`, `/_matrix/federation/v1/version`, `query/profile`, `make_join`, `send_join` (v2) and `send`, and [`ProfileService`](xref:Uniform.Matrix.Server.Accounts.ProfileService) asks other servers for their users' profiles.

Joins: [`RoomService.JoinAsync`](xref:Uniform.Matrix.Server.Rooms.RoomService.JoinAsync*) sends joins of room IDs of other servers that are not here to [`RemoteJoins`](xref:Uniform.Matrix.Server.Federation.RemoteJoins), which asks the room's server for a `make_join` template, signs it, sends it with `send_join`, checks the content hash and the sender server's signature of every returned event, and stores the room with [`EventSender.StoreJoinedRoomAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.StoreJoinedRoomAsync*). The returned state and auth chain get negative stream positions, so they sort as history before the join and never count as new. On the resident side [`EventSender.MakeMembershipAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.MakeMembershipAsync*) builds the template and [`AcceptMembershipAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.AcceptMembershipAsync*) checks the signed join (its ID, hash, origin and the auth rules) before storing it like a local event. Auth chains are not yet checked against the auth rules.

Transactions: `/send` hands each PDU to [`RemoteEvents`](xref:Uniform.Matrix.Server.Federation.RemoteEvents), which first asks the sending server for up to 20 events missing before it (`get_missing_events`) and accepts them oldest first, then hands the PDU to [`EventSender.AcceptEventAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.AcceptEventAsync*), which checks its hash, the sender server's signature and the auth rules against the current state (not yet the state before the event, which matters once rooms fork), and stores it; an event replaces only the forward extremities it builds on. [`FederationSender`](xref:Uniform.Matrix.Server.Federation.FederationSender) follows [`ServerStream`](xref:Uniform.Matrix.Server.Sync.ServerStream) and hands local users' events, remote joins this server accepted, and local users' device changes (`m.device_list_update`) to [`FederationQueue`](xref:Uniform.Matrix.Server.Federation.FederationQueue). The queue keeps one batch per destination (up to 50 PDUs and 100 EDUs per transaction) and retries failures with pauses doubling from 2 seconds to 5 minutes; a 4xx refusal other than 429 drops the batch. PDUs and the EDUs that matter later are also kept in the `FederationOutbox` table until sent, and [`FederationQueue.ResumeAsync`](xref:Uniform.Matrix.Server.Federation.FederationQueue.ResumeAsync*) queues them again at start; typing and presence stay in memory. [`RemoteActivity`](xref:Uniform.Matrix.Server.Federation.RemoteActivity) sends and receives typing (`m.typing`) and public read receipts (`m.receipt`); [`RemoteDevices`](xref:Uniform.Matrix.Server.Federation.RemoteDevices) handles keys across servers (`user/keys/query`, `user/keys/claim`, `user/devices`) and to-device messages (`m.direct_to_device`). Presence is not shared between servers yet.

Invites of other servers' users: [`RemoteInvites`](xref:Uniform.Matrix.Server.Federation.RemoteInvites) signs the invite with [`EventSender.SignAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.SignAsync*) (built and checked, not stored), sends it with `invite` v2 and the stripped room state from [`EventSender.InviteRoomStateAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.InviteRoomStateAsync*), checks that the invitee's server signed the same event, and stores it through [`AcceptEventAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.AcceptEventAsync*). Receiving invites is not there yet.

Joins and leaves of other servers' users go through [`EventSender.MakeMembershipAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.MakeMembershipAsync*) and [`AcceptMembershipAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.AcceptMembershipAsync*); [`RemoteJoins.RejectInviteAsync`](xref:Uniform.Matrix.Server.Federation.RemoteJoins.RejectInviteAsync*) rejects an invite to a room not here through the inviting server. [`RemoteJoins.ResolveAliasAsync`](xref:Uniform.Matrix.Server.Federation.RemoteJoins.ResolveAliasAsync*) asks `query/directory` for aliases of other servers. [`RoomHistory`](xref:Uniform.Matrix.Server.Federation.RoomHistory) answers `get_missing_events`, `backfill`, `event`, `state` and `state_ids` for servers with a member in the room. Presence of local users goes out as `m.presence` EDUs from [`FederationSender`](xref:Uniform.Matrix.Server.Federation.FederationSender); [`PresenceService.SetRemoteAsync`](xref:Uniform.Matrix.Server.Accounts.PresenceService.SetRemoteAsync*) keeps remote users' presence, which their server ends.

Version 12 rooms are created by [`EventSender.CreateHashedRoomAsync`](xref:Uniform.Matrix.Server.Rooms.EventSender.CreateHashedRoomAsync*), which signs the create event before the room row exists, as the room ID is its hash. The default room version stays 10 until clients send `via` when joining by ID.

Sliding sync ([`SlidingSyncService`](xref:Uniform.Matrix.Server.Sync.SlidingSyncService), `POST /_matrix/client/unstable/org.matrix.simplified_msc3575/sync`) builds rooms with [`SyncService`](xref:Uniform.Matrix.Server.Sync.SyncService), from the start for rooms a connection has not had and since its position for the others, and reshapes them into lists, room subscriptions and the to-device, e2ee, account data, receipts and typing extensions. Connections live in memory; an unknown position gets `M_UNKNOWN_POS`.

`Server:TrustedProxies` turns on ASP.NET Core's forwarded headers for those addresses only.

Room summaries (`/v1/room_summary` and the unstable `im.nheko.summary` paths) and space hierarchies (`/v1/rooms/{roomId}/hierarchy`, local rooms only, and `/_matrix/federation/v1/hierarchy` for other servers) come from [`DirectoryService`](xref:Uniform.Matrix.Server.Rooms.DirectoryService), shown to members and invitees, and to anyone for public, knockable or world-readable rooms. [`SyncService`](xref:Uniform.Matrix.Server.Sync.SyncService) answers `/v1/rooms/{roomId}/relations` (found by the related event's ID in the stored JSON, then checked) and `timestamp_to_event`. Reports of content, rooms and users are logged at warning level under `Uniform.Matrix.Server.Reports`, as there is no review list yet.

Media of other servers: [`MediaService`](xref:Uniform.Matrix.Server.Media.MediaService) fetches it on first use with [`FederationClient.DownloadAsync`](xref:Uniform.Matrix.Server.Federation.FederationClient.DownloadAsync*) from `/_matrix/federation/v1/media/download` (a `multipart/mixed` answer: metadata, then the file; redirects to elsewhere are not followed), falling back to the legacy unsigned `/_matrix/media/v3/download` of older servers, and keeps it under an ID of its own in `RemoteMedia`; thumbnails of it are made here. The federation media endpoints serve local media the same way. The unauthenticated legacy reads, when turned on, serve local media only, so nobody without an account can make the server fetch from others.

[`FederationSender`](xref:Uniform.Matrix.Server.Federation.FederationSender) keeps how far it got in `FederationProgress`, so events stored just before a stop are still sent after the restart.

Older clients use `r0` paths and unstable key backup and cross-signing paths; [`LegacyPaths`](xref:Uniform.Matrix.Server.Http.LegacyPaths) maps them to `v3` before routing. Requests no endpoint knows are logged with method and path, without the query.

Room version 12 ([`RoomVersion.V12`](xref:Uniform.Matrix.Protocol.Server.RoomVersion.V12), [`RoomIdIsCreateHash`](xref:Uniform.Matrix.Protocol.Server.RoomVersion.RoomIdIsCreateHash)): the room ID is `!` and the create event's hash, the create event has no `room_id` and is left out of `auth_events`, and the creators (the sender and `additional_creators`, see [`AuthRules.Creators`](xref:Uniform.Matrix.Protocol.Server.AuthRules.Creators*)) have unlimited power and cannot be listed in power levels. Such rooms can be joined through `via` servers, since their IDs name no server; creating them here is refused until room creation builds the create event before the room's row. `FederationTests` run two servers in memory whose federation clients reach each other through a test handler.

HTTPS comes from [`TlsCertificate`](xref:Uniform.Matrix.Server.Http.TlsCertificate) (in `Http/`), which reads the PEM files of `Tls:*`, sends the intermediates with the certificate (other servers check the chain) and reads the files again within a minute of a renewal.
