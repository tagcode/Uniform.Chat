# View models

[`MainViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.MainViewModel) switches `Page` between [`LoginViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.LoginViewModel), [`ConnectingViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.ConnectingViewModel) and [`ChatViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.ChatViewModel); [`MainView`](xref:Uniform.Chat.Avalonia.Views.MainView) picks the view by data template.

[`ChatViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.ChatViewModel) follows the engine's events on a background task: it reads [`SyncProcessor.Changes`](xref:Uniform.Matrix.Client.Services.SyncProcessor.Changes) and posts each batch to the UI thread through [`IUiDispatcher`](xref:Uniform.Chat.Avalonia.Services.IUiDispatcher), where room state is read under [`SyncProcessor.Read`](xref:Uniform.Matrix.Client.Services.SyncProcessor.Read*). [`ConnectionStatus.Changed`](xref:Uniform.Matrix.Client.Services.ConnectionStatus.Changed), [`EventsDecrypted`](xref:Uniform.Matrix.Client.Services.SyncProcessor.EventsDecrypted) and [`OutboxSender.RoomChanged`](xref:Uniform.Matrix.Client.Services.OutboxSender.RoomChanged) are posted the same way. Each posted change runs inside a try/catch that logs, as an exception on the UI thread would end the app.

[`MessageList`](xref:Uniform.Chat.Avalonia.ViewModels.MessageList) turns events into [`MessageViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.MessageViewModel) items. Edits, deletions and reactions change the item they refer to instead of adding one, also when older history arrives after them. Unsent outbox messages are shown last; their list is reloaded on every outbox change, and a version counter drops loads that finish out of order, so a sent message never comes back as pending.

Room creation, invites, deletions, typing notices, read markers and file uploads call [`MatrixClient`](xref:Uniform.Matrix.Protocol.Client.MatrixClient) directly; messages, replies, edits and reactions go through the outbox. Files to encrypted rooms are encrypted with [`UploadEncryptedAsync`](xref:Uniform.Matrix.Client.EncryptedMedia.UploadEncryptedAsync*) and their message is sent through the outbox, which encrypts it.

[`SecurityViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.SecurityViewModel) shows `GetSecurityStatusAsync` and offers set-up, recovery or verification by what is missing; it waits for [`CryptoService.WhenStarted`](xref:Uniform.Matrix.Client.Services.CryptoService.WhenStarted), as encryption starts after sign-in. Setting up recovery asks for the password only when the server answers with a user-interactive auth challenge. [`ChatViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.ChatViewModel) follows [`CryptoService.VerificationChanged`](xref:Uniform.Matrix.Client.Services.CryptoService.VerificationChanged) and shows one [`VerificationViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.VerificationViewModel) at a time, so incoming requests and our own requests go through the same panel.

[`ChatViewModel`](xref:Uniform.Chat.Avalonia.ViewModels.ChatViewModel) also decides on notifications: new messages in direct chats, messages whose `m.mentions` name the user or the room, and invites that were not in the list before, at most three per sync and none from history or the first sync. They are passed to [`GuiPlatform.Notifier`](xref:Uniform.Chat.Avalonia.GuiPlatform.Notifier) unless the window has the focus on that room. The desktop app sets [`FreeDesktopNotifier`](xref:Uniform.Chat.Desktop.Notifications.FreeDesktopNotifier) on Linux, which calls `org.freedesktop.Notifications.Notify` over the session bus with Tmds.DBus.Protocol, the D-Bus library Avalonia already uses.
